# 設計の考え方

Muu は、利用者が打つ文字のすべてを受け取るプログラムです。そのため、何を外に出さないか、利用者のデータをどう扱うかを、機能より先に決めています。この章では、その考え方を説明します。Swift と Rust の役割分担や、失敗したときに入力を止めない仕組みは、[全体構成](./architecture.md) で説明します。

## 変換は端末の中で完結する

変換は Mac の中の Rust のエンジンだけで行います。読み、候補、確定した文字列をネットワークへ送ることはありません。エラーの情報とログにも、読み、候補、確定した文字列、押したキーの文字は出しません。何かがおかしくなって調べるときに残るのは、件数や結果コードのような、入力の中身を含まない情報だけです。

## 通信する場面を限る

Muu が通信するのは、利用者が明示的に操作した 2 つの場面だけです。1 つは郵便番号データの更新で、「郵便番号データを更新…」を実行したときに日本郵便のサイトから取得します。もう 1 つは変換モデルの取得で、About で取得を押したときに、版を固定した 1 つのファイルをダウンロードします。

自動の更新、バックグラウンドの通信、使用状況の送信はありません。辞書の取り込みもファイルからだけで、ダウンロードはしません（[データと通信](../usage/data-and-network.md)）。

## 学習と辞書は利用者のもの

ユーザー辞書、取り込んだ辞書、郵便番号データ、変換学習は、どれも利用者の Mac の中に保存します。変換学習が保存するのは、辞書の語の番号と、選んだ回数・退けた回数だけです。読みや表層、時刻、どのアプリで打ったかは保存しません。学習はメニューからいつでも削除できます。

利用者のファイルを、Muu が黙って書き換えることもしません。読めない辞書のファイルは読み取り専用にして元のまま守り、利用者が直すか置き換えるのを待ちます。学習のファイルが不正なときは、元のファイルを退避してから空の学習で始め、元のファイルは消しません。退避できないときや、辞書がなくて検証できないときは、ファイルに触れずに学習の保存を止めます（[データの保存](./storage.md)）。

## 記録は開発用の版だけ

変換を後から調べるための記録は、読みと確定した文字列を平文で残します。これは開発には役に立ちますが、利用者の入力をそのままファイルに残すものです。そのため、記録は明示して作った dogfood 版でだけ使えるようにし、配布する版では設定を変えても有効にならないようにしています。

設定ではなくビルドで分けているのは、設定は同じ利用者のほかのプロセスからも書き換えられるからです。設定だけで有効にできると、そのプロセスが入力監視の許可なしに、利用者の入力を残させて読めてしまいます（[ビルドとテスト](./build-and-test.md)）。

## 同梱するものは条件を確かめる

辞書とデータは、ライセンスの条件を確かめたものだけを同梱し、帰属の表示を app の中に入れています。変換モデルは、tokenizer や学習データの条件から同梱せず、利用者が上流から直接取得する形にしています（[ライセンスと既知の制限](./licenses-and-limitations.md)）。
