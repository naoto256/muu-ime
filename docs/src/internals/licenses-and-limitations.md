# ライセンスと既知の制限

この章では、Muu が同梱しているデータとそのライセンス、取得して使うモデルの条件、そしていま分かっている制限をまとめます。

## 本体のライセンス

Muu IME 本体のコードは MIT License です（`LICENSE`）。同梱しているデータと依存のライセンスの原文と帰属は、`THIRD_PARTY_LICENSES/` にまとめ、app の中にもそのまま入れています。

## 同梱しているデータ

### システム辞書

システム辞書の元は、Google の Mozc が公開している辞書（Mozc OSS）です。語彙と、語どうしのつながりのコストは Mozc に従い、名詞と固有名詞を SudachiDict-core から補っています。Mozc の辞書は BSD-3-Clause に、NAIST、ICOT、沖縄のパブリックドメインの条件が加わったもので、SudachiDict-core は Apache-2.0 と、UniDic に由来する部分の BSD-3-Clause です。SudachiDict の `LEGAL` は原文のまま同梱しています。

どの版のソースを使ったかは、`dict-src/provenance.toml` に版とハッシュで固定しています。更新は手で行い、自動では取り込みません。Mozc は未知語のモデルを配布していないので、未知語の扱いは Muu が独自に作ったものです。ローマ字の表も Muu の独自のデータで、既存の入力メソッドの表は流用していません。

辞書は、commit 済みのソースから毎回同じ手順で作り、2 回作って同じバイト列になること、固定したハッシュと一致することを検査しています。

share-alike（CC BY-SA など）や GPL のデータは、既定の同梱には入れていません。

### 郵便番号データ

郵便番号から住所への変換には、日本郵便の「住所の郵便番号（1 レコード 1 行、UTF-8 形式）」を使います。日本郵便は、このデータの著作権を主張せず、自由な再配布を認めています（[形式説明のページ](https://www.post.japanpost.jp/service/search/zipcode/download/utf-readme.html)）。

app には、2026-07-31 の配布版から作った初期データを入れています。取得した ZIP と CSV のハッシュ、作ったデータのハッシュと件数は、データと一緒に保存する manifest に記録します。利用者が更新すると、[配布ページ](https://www.post.japanpost.jp/service/search/zipcode/download/utf-zip.html)から最新のデータを取得して作り直します。

### Rust の依存と標準ライブラリ

app に入る Rust の依存の crate と、Rust の標準ライブラリのライセンスの原文と著作権表示も同梱しています。どのライセンスを選ぶか、どの表示を残すかは、レビュー済みの一覧（manifest）が正本です。ビルドのたびに、実際に app へ入る依存と標準ライブラリの部品がこの一覧と一致するかを確かめ、食い違えば止まります。一覧を自動で作り直して通すことはせず、レビューに戻します。上流の原文は、改行や末尾の空行も含めてバイト列のまま残します。

app に同梱したライセンスのファイル一式も、許可した一覧と完全に一致するかを検査します。手で書き換えたもの、余分なファイル、symlink があれば止まります。

## 変換モデル

変換モデルは、どちらも同梱していません。利用者が About から取得したときだけ、上流から直接ダウンロードします。Muu がモデルを再配布することはありません。

- **zenz-v3.2-small**（利用者が取得するモデル）: Miwa-Keita/zenz-v3.2-small-gguf の、版と SHA-256 を固定した 1 つのファイルを取得します。モデルカードは Apache-2.0 を宣言しています。tokenizer は、語彙と結合の規則が ku-nlp/gpt2-small-japanese-char と一致しており、そちらは CC BY-SA 4.0 です。学習データと重みの元は、公開されている資料からは特定できませんでした。Muu は、zenz の公開者が示した条件に従って使う立場で、上流の条件が満たされているかどうかは公開者の側の責任としています。
- **kanakanji-edge-33m**（開発用のモデル）: 重みは Apache-2.0、tokenizer は京都大学 黒橋研究室の ku-nlp に由来する CC BY-SA 4.0、学習データは Miwa-Keita/zenz-v2.5-dataset で CC BY-SA 4.0 と ODC-BY です。tokenizer と学習データが CC BY-SA 4.0 なので、同梱しません。

edge の帰属を、推測で zenz に当てはめることはしません。About と NOTICE には、zenz の取得先、固定した版と SHA-256、宣言されたライセンス、tokenizer の出典を書いています。

## 評価データ

変換品質の検査に使う AJIMEE-Bench の 200 件は、Japanese Wikipedia Input Error Dataset v2 に由来し、CC BY-SA 3.0 です。検査のときに明示的に取得し、app には入れません。このデータを再配布するときは、上流の帰属と CC BY-SA 3.0 の表示を残してください。

## 既知の制限

### まだないもの

パスワード欄などのセキュア入力の検出、アプリごとの互換の設定、再変換、エラーメッセージの翻訳は、まだありません。

### 動作の制限

- **ある活用の語が変換に出ない。** 品詞 `HA_GROUP1_VERB` の語は、ファイルの形式と変換用の活用表とで語尾の定義が食い違っていて、登録しても変換に出ません。直し方はまだ決めていません。
- **取り込み辞書を上限まで使うとメモリが大きい。** 上限いっぱい（32 個の辞書、活用を展開して約 100 万語）の合成データでは、編集中に新旧の語彙が並ぶこともあって、メモリの使用量が 1.4 GiB を超えました。入力メソッドとしては、上限そのものが大きすぎるかもしれません。見直しはまだです。
- **郵便番号の更新の途中で落ちると、古いデータに戻る。** 郵便番号は公開してから保存するので、その間にプロセスが落ちると、次の起動では更新前のデータになります（[データの保存](./storage.md)）。
- **表示が壊れたときの回復には限りがある。** 応答の表示用の情報が壊れて確定だけを救った場合、次の文字の未確定文字列は、次の応答まで表示されません。その間にクリックや入力先の切り替えがあると、その文字は確定されません。
- **変換モデルがないと About に印が付く。** モデルを取得していない環境では、About の項目に注意の印が付いたままになります。
- **学習しても揺れる語がある。** 文脈で使い分ける語では、学習しても候補が入れ替わり続けることがあります（[変換の流れ](./conversion.md)）。

### アプリによる違い

入力メソッドの動きは、入力先のアプリの実装に左右されます。実機で次のことを確認しています。

- Discord などの Electron 製のアプリや、Tauri 製のアプリの一部は、カーソルの位置を正しく返しません。別の問い合わせ方で位置が分かれば候補パネルを出し、分からなければ出しません。変換とキーでの候補の選択は、どちらの場合もできます。
- Shift だけを押したことが Muu に届くかどうかも、アプリによって違います。メモでは常に届き、Discord では入力中だけ、Claude.app では届きません。Esc と Shift+英字は、どのアプリでも使えます。
- Ghostty では、候補パネルが文節に追従しません。Ghostty は、どの範囲を問い合わせてもカーソルの点を返し、注目している文節の情報を捨てるためです。アプリごとの補正は入れないことにしています。
- Apple のターミナルでは、注目している文節の下線が逆の位置に描かれることがあります。候補パネル自体は正しい文節に付いています。
- Cmd+Space を macOS の入力ソースの切り替えに使っていると、そのキーは Muu に届かず、未確定文字列は確定されます。

### 確かめていないこと

JIS キーボードの英数・かなのキーがふつうのキーとして届くかどうか、フルスクリーンや別のスペースでのモードバッジの表示、別の Mac で辞書を作ったときに同じハッシュになるかどうかは、まだ確かめていません。
