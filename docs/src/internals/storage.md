# データの保存

Muu が保存するのは、ユーザー辞書、取り込んだ辞書、郵便番号データ、変換学習の 4 つと、開発用の版だけで使う記録です。どれも利用者の Mac の中に置きます。この章では、それらをどう書き、失敗したときにどう守るかを説明します。

## Swift が書き、Rust が形式を決める

ファイルの読み書きは Swift が行います。けれども、ファイルの中身の形式を決め、読んだものを解釈して検証し、書くバイト列を作るのは Rust です。Swift は、Rust が作ったバイト列をディスクに置き、ディスクから読んだバイト列を Rust に渡すだけで、中身を解釈しません。

こうしているのは、形式の規則を 1 か所にまとめるためです。同じファイルを Swift と Rust がそれぞれの規則で読むと、片方だけが受け入れる内容が生まれます。たとえば、Swift では通るのに Rust の変換用の層では弾かれる辞書があると、画面には語が並んでいるのに変換に出ない、という食い違いになります。規則を Rust に集めておけば、管理画面に出す一覧も、変換に効く語彙も、同じ解釈から作られます。

反対に、Rust はファイルのパスを知りません。取り込み辞書のように、起動時に追加のファイル（辞書ごとの本体）が必要になる場合でも、Rust は「この内容のハッシュの名前のファイル」という形で求め、Swift は自分が管理するディレクトリの中だけを、その名前の規則で開きます。Rust が返した任意のパスを Swift が開くことはありません。

読み込みで「ファイルがない」と判断するのは、ファイルを開いたときに「存在しない」と返された場合だけです。権限がない、種類が違う、大きすぎる、といった失敗は「読めない」として区別します。読めなかったものを「ない」として扱うと、空の内容で上書きしてしまうおそれがあるからです。

## 壊れたファイルは上書きしない

辞書のファイルが読めないとき、Muu はそれを直そうとしたり、空にして保存し直したりしません。

**形式そのものが読めない**場合（ヘッダが違う、行が壊れている、など）は、そのデータを読み取り専用にします。自動の保存も、不要になったファイルの掃除も止めて、元のファイルに一切触れません。利用者がファイルを置き換えるか、郵便番号なら明示的に更新し直すまで、そのまま待ちます。

**形式は読めるが、変換に使う規則に当たる**場合もあります。たとえばユーザー辞書で、1 つのよみに登録した単語が多すぎる場合です。このとき Rust は、ファイルを解釈した**管理用の内容**（一覧に出す全項目）はそのまま持ち、変換に効く**有効な層**だけを空にします。管理画面には全項目が並ぶので、利用者は一覧から削除して直せます。規則に収まった時点で、層はまた有効になります。

規則に当たらない語だけを拾って使う、ということはしていません。どの語を落とすかで変換の結果が変わってしまい、利用者の知らないところで別の辞書になってしまうからです。

読んだだけで保存し直すこともしません。古い形式のファイルでも、利用者が編集して保存するまでは、元のバイト列のまま残します。

## 作ってから差し替える

ファイルを書くときは、いきなり上書きせず、同じディレクトリに一時ファイルを書いて fsync し、名前を変えて置き換え、最後にディレクトリを fsync します。途中で失敗したりプロセスが落ちたりしても、元のファイルか新しいファイルのどちらかが完全な形で残ります。

ディレクトリは本人だけが読み書きできる権限（0700）、ファイルは 0600 で作ります。読み込むときは、通常のファイルだけを、大きさの上限付きで開きます。保存先の途中のディレクトリが symlink になっている場合は、読むことも書くこともしません。

置き換えのあとのディレクトリの fsync に失敗した場合は、「保存はしたが、耐久性を確認できなかった」として、保存の失敗とは区別して画面に出します。

## 辞書の編集は 1 つの取引にする

辞書の編集には、ディスクへの保存と、変換に効く語彙の差し替えの 2 つがあります。この 2 つがずれると、画面では保存に失敗したと出ているのに、変換だけが新しい語を使い続ける、ということが起きます。

そこで、辞書の編集は「準備 → 保存 → 公開 → 完了」を 1 つの取引として、データごとに 1 つずつ順に進めます。

1. **準備**: Rust が、保存するバイト列と、次に公開する語彙を作ります。まだ公開はしません。
2. **保存**: Swift がバイト列をディスクに書きます。
3. **公開**: Rust が語彙を差し替えます。公開には「この版の内容に対する編集であること」という条件を付け、その間に別の編集が入っていれば拒否します。
4. **完了**: 画面に結果を返します。

公開を拒否されたら、保存したファイルを元に戻します。戻すことにも失敗した場合の扱いが、データごとに少しずつ違います。

- **ユーザー辞書**は、保存してから公開します。公開を拒否されたら、元のバイト列へ戻すのを最大 3 回試します。それでも戻せなければ、元のバイト列を同じフォルダの `user-dictionary.recovery-<番号>.tsv` へ、解釈せずにそのまま退避し、編集を止めます。この退避ファイルは自動では読み込みません。そのときのディスクには公開を拒否された新しい内容が、退避ファイルには元の内容が入っていて、どちらに戻すかは利用者が決めることだからです。
- **取り込み辞書**は、辞書の本体、世代の記述、現在の世代を指すポインタの 3 段で保存し、ポインタを書き換えた時点で確定します。ポインタを書く前に失敗したら、Rust の語彙を元に戻します。戻すのにも失敗し、整合を取り戻せない場合は、Muu を終了します。次の起動では、ディスクの内容だけを正として読み直します。
- **郵便番号**は、取り込み辞書とは逆に、公開してから保存します。保存に失敗し、元に戻すことも、改めて保存し直すこともできない場合は、郵便番号の層だけを空にして、ほかの変換は続けます。次の起動では、ディスクに残っている郵便番号データから読み直します。この順序のため、公開から保存の確定までの間にプロセスが落ちると、次の起動では古いデータに戻ります。

どの取引でも、準備した内容は Rust の中に予約として残ります。公開しなかった取引は Swift が必ず取り消します。取り消しに失敗したら、Rust に予約が残ったままかもしれないので、その辞書の編集を止め、再起動を案内します。

## 変換学習の保存

学習は、辞書とは違う形で保存します。学習は確定のたびに少しずつ変わり、利用者が保存の結果を待つこともないからです。

学習の状態は Rust の Core が持ち、`(世代, 版)` という番号で表します。版は学習が変わるたびに進み、世代は利用者が学習を削除したときに進みます。Swift は、受け取った最後の番号を添えて Core に問い合わせ、それより新しい状態があれば、そのバイト列を受け取って保存します。中身は Swift から見て不透明なバイト列で、Swift は解釈しません。

保存は最後の更新から 250 ms 後にまとめて 1 回行い、打鍵のたびには書きません。ふつうの書き込みの失敗では、間隔を延ばしながら再試行します。保存先が安全でない場合のように、繰り返しても直らない失敗では、その起動の間は保存を止めます。

起動時に学習のファイルが不正だった場合や、使っているシステム辞書の fingerprint と一致しない場合は、元のファイルを退避して、空の学習から始めます。別の辞書の版向けに作られた、それ自体は正しいファイルかもしれないので、消したり上書きしたりはしません。システム辞書を開けなかった場合は、学習を検証できないので、ファイルに触れず、その起動の間は保存もしません。

学習の削除は、ディスクを先に消してから Core に伝えます。順序を逆にすると、Core を空にしたあとでディスクの削除に失敗したとき、古い学習が残ってしまいます。起動時に退避した古いファイルを先に消し、現在のファイルを最後に消すのも同じ理由です。途中で失敗したときに、現在の学習がまだ残っている状態にしておけば、「削除できなかった」と正しく伝えられます。

## 記録

変換を後から調べるための記録（commit stream）は、開発用の dogfood 版だけで使えます。配布する版では、設定を変えても有効になりません（[ビルドとテスト](./build-and-test.md)）。

記録は、確定した変換 1 件につき 1 行の JSON です。変換した時点の事実（読み、第一候補、言語モデルが替えたかどうかとその判断）と、確定した時点の事実（最終の文節と候補、手で選んだか、文節を動かしたか）の 2 つの部分を持ちます。どちらも、実際の文節列をその場で写し取ったもので、後から推測で組み立て直したものではありません。形式は `muu.commit-stream.v5` です。

記録の失敗で、確定を失敗させることはしません。記録の準備や書き込みに失敗したら、その記録を捨てて、確定と学習はそのまま通します。捨てた件数は次の記録に書き添えるので、読み手は欠けたことが分かります。

記録の中身を作るのは Rust で、Swift は受け取った 1 行の中身を解釈せず、空でないこと、大きさの上限、改行を含まないことだけを確かめてファイルへ追記します。ファイルは 8 MiB ずつ 8 本まで持ち、書きかけの行が残ったファイルには追記せず、新しいファイルに移ります。

## 保存する場所

ユーザーデータは `~/Library/Application Support/dev.muu.inputmethod.Muu/` の下に、データごとのフォルダで置きます。

- `user_dict/user-dictionary.tsv`: ユーザー辞書。1 行目がヘッダで、各行は「よみ・単語・品詞・優先度・CRC32」のタブ区切りです。
- `imported_dict/v2/`: 取り込み辞書。辞書ごとの本体（内容のハッシュの名前）、世代の記述、現在の世代を指すポインタを置きます。
- `postal_code/v1/`: 郵便番号データ。世代ごとの TSV と manifest、現在の世代を指すポインタを置きます。
- `personal_frequency/personal-frequency-v1.json`: 変換学習。辞書の語の番号と回数だけを持ち、使った辞書に結び付けます。

変換モデルと開発用の記録は、別の `~/Library/Application Support/MuuIME/` の下に置きます。システム辞書と郵便番号の初期データは app に同梱しています。
